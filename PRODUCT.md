# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Developers and presenters who author Marp decks and want reusable techniques
they can adapt for their own talks.

## Product Purpose

marp-demo is a playground of complete Marp presentations. Each deck demonstrates
a technique, such as animation methods, slide keyframes with morph transitions,
synchronized simulations, or contrasting visual styles, with the working source
beside it.

Success happens in order: visitors are first convinced that Markdown slides can
look and move like this, then copy a working technique into their own deck.

## Positioning

Every technique is a real, tested deck built from plain Markdown, theme CSS,
native SVG, and small local scripts on a pinned Marp CLI. Each one ships as an
interactive HTML presentation and a readable PDF, with browser tests that verify
its behavior and fallbacks, so visitors copy working code rather than screenshots.

## Operating Context

- Published on GitHub Pages at https://chris-ayers.com/marp-demo/ under the
  `/marp-demo/` project path, with a landing page that links every deck and PDF.
- Presented in a browser with the arrow keys; interactive controls are used in
  the audience window, while presenter views stay static.
- Source is read on GitHub; the README documents each deck, its files, and how
  to build (`npm run build`), preview (`npm run preview`), and test (`npm test`).
- GitHub Actions builds, tests, and deploys on Ubuntu 22.04, so the published
  PDFs are rendered on a Linux runner.

## Capabilities and Constraints

- Assets are local only: no CDN, remote fonts, or external runtime requests.
- HTML and PDF exports must tell the same story; PDFs keep complete, static
  states rather than mid-animation frames.
- Reduced-motion, print, presenter, and no-JavaScript views remain complete and
  readable.
- Behavior and fallbacks are verified with Playwright browser tests.
- Marp CLI is pinned (4.5.1), and dependencies are locked.
- HTML and local file access are enabled during builds, so only trusted Markdown
  and assets are built.
- MIT licensed; bundled third-party assets keep their own licenses beside them.

## Product Principles

1. Convince, then equip: show the compelling result first, then make the source
   that produces it easy to find and read.
2. Copyable over clever: a technique should survive being lifted into another
   Marp deck with its CSS, markup, and any runtime it needs.
3. Prove it: claims about behavior, fallbacks, and accessibility are backed by tests.
4. Complete without motion: every animated idea also works as a static slide.
5. Local by default: nothing at runtime depends on a third-party service.

## Accessibility & Inclusion

- Text must meet WCAG 2.2 AA contrast in every deck and style.
- Respect `prefers-reduced-motion`; controls must be keyboard operable and labeled.
- Print, PDF, presenter, and no-JavaScript views keep the complete content.
